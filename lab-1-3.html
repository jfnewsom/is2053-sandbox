2
Nested Houston Logic
← Back: CP1

The heart of this assignment: if the player reaches Houston, they can choose to continue to Galveston. This is an if inside an if, a nested if.

Why This Matters

Nested decisions are how programs make sense of the real world. Real decisions aren't flat. They branch. Reach Houston? Then ask about Galveston. Loaded payment info? Then show the checkout button. The pattern of "if a particular thing happened, ask a follow-up question" lives at the heart of every non-trivial program you'll ever write.

Step-by-Step Instructions

Replace your Houston branch (elif choice == 2) with nested logic. Subtract first, then check. That way miles_remaining always means the miles left AFTER the drive, which is exactly what the Trip Summary reports.

  1. Subtract the leg you just drove: miles_remaining = miles_remaining - SAT_TO_HOUSTON
  2. Check if miles_remaining >= 0. That is how you know they reached Houston
  3. If they made it: set distance to SAT_TO_HOUSTON, print the arrival line and the miles remaining, then ask 'Continue to Galveston? (y/n): '
  4. If they answer y/Y: update the destination to Galveston, set distance to SAT_TO_HOUSTON + HOU_TO_GALVESTON, subtract again with miles_remaining = miles_remaining - HOU_TO_GALVESTON, then check if miles_remaining >= 0 and set status to WINNER or SHORT
  5. Subtract on the Galveston leg even when they fall short. That is why the sample Trip Summary shows Miles Remaining: -50. If you only subtract on success, your output will not match
  6. If they answer anything else: set status to 'STOPPED'
  7. If they did not reach Houston: set status to 'SHORT' and set distance to SAT_TO_HOUSTON
Test Your Code

Test all 4 Houston outcomes:

  1. Roll 5, choice 2: Did not reach Houston → SHORT
  2. Roll 20, choice 2, 'n': Reached Houston, chose to stay → STOPPED
  3. Roll 20, choice 2, 'y': Reached Houston with 0 miles left, so Galveston is out of reach → SHORT, and the summary reads Miles Remaining: -50
  4. Roll 25, choice 2, 'y': Reached Houston with 50 left, exactly enough → WINNER. Roll 25 is above the prompt's stated range; enter it anyway to test this path, as the Design Note in Checkpoint 1 explains
What You Should Have
  1. Nested if inside the Houston branch
  2. Input prompt asking about Galveston
  3. Logic handling y/Y for continue, anything else for stop
  4. All 4 Houston outcomes working correctly

Checking before subtracting Subtract first, then compare to 0. Checking miles_remaining >= SAT_TO_HOUSTON gets the arrival test right but leaves miles_remaining wrong in the Trip Summary.
Print Order Rule

Only print the final outcome ONCE, after all decisions are made. If the player chooses Houston, do not print a Houston arrival message before the Galveston prompt. The prompt comes first, then a single result printed after the if-elif-else fully resolves. Two prints for one game = wrong.

If Something Breaks

Common failure patterns and where they came from:

Symptom Where to Look
NameError: name 'HOU_TO_GALVESTON' is not defined Check CP1 (Setup & New Variables): you didn't add the new constant at the top of your file. Should be HOU_TO_GALVESTON = 50.
NameError: name 'distance' or 'miles_remaining' is not defined in the Trip Summary Check CP1 (Setup & New Variables): you didn't initialize the tracking variables BEFORE the if-elif-else chain. They must exist before any branch references them.
Houston branch always continues to Galveston even when the player types 'n' Check CP2 (Nested Houston Logic): your or condition is wrong. The correct pattern is continue_choice == 'y' or continue_choice == 'Y'. Writing continue_choice == 'y' or 'Y' is always True (a common gotcha).
IndentationError on the inner Galveston check Check CP2 (Nested Houston Logic): nested code must be indented FURTHER than the outer if. The inner if miles_remaining >= 0 (after subtracting HOU_TO_GALVESTON) sits inside the outer if continue_choice == 'y', so it gets two levels of indentation.
Trip Summary shows Status: STOPPED or other status but the closing message is wrong (or missing) Check CP4 (Trip Summary & Final Message): verify your final if-elif-else checks the exact uppercase status strings ('WINNER', 'SHORT', 'DETOUR') with consistent quotes. Python is case-sensitive.
Player chose Corpus, fell short, but Trip Summary shows Status: ERROR or Distance: 0 Check CP3 (Update Other Branches): the Corpus branch is missing the distance or status assignment. Every branch needs to set both.
NameError: name 'status' is not defined at the closing message Check CP3 (Update Other Branches): one of your branches (probably the else/invalid case) doesn't set status. The tracking variable defaults in CP1 should cover this, but verify the defaults are present.
